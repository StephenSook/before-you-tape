- `src/pages/PackPage.tsx`: reads and second looks get a `stillAllowed` check that reads the live consent, cloud switch and connection. The page keeps the latest switch and connection in a ref, because a read already running holds the props from when it began. So switching cloud checks off, by Remote Config or the sender, stops any further cloud call of a read already under way. Source: comparing the web and Android kill-switch windows. Verified: a new `src/pages/PackPage.test.tsx` case turns the switch on while the first cloud call is pending, then fails that call with a 503. No retry, no fallback, no card. - `src/ai/itemRead.ts` and `src/ai/secondLook.ts`: `readItem` and `runSecondLook` take a `stillAllowed` check and ask it before every further cloud call: the automatic retry, the fallback model, and the cloud recovery after a failed hybrid call. If cloud checks were switched off meanwhile, the read stops as blocked. Only a call already in flight can finish. Before, a read that started with the cloud allowed could still make its retry and its fallback call after the switch went off. The check defaults to always allowed, so other callers are unchanged. Source: comparing the web and Android kill-switch windows for the limits note.
