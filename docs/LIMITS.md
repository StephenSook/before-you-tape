# Known limits

What the app cannot catch on its own, and what it relies on the sender for.

- When a label has "ALCOHOL" at the end of one line and "FREE" at the start of the next, the app asks "Does the label say alcohol-free?". It takes the sender's answer as given: a "yes" on a label whose next line is really "FREE SHIPPING" reads "OK to pack".
- The rules behind each verdict were read on a stated date, and the app marks a layer stale once that read is older than its limit: 120 days for the USPS export rules, 60 days for a country's rules and customs notes, 21 days for USPS service suspensions. While any layer is stale, nothing reads "OK to pack"; it reads "Check this" until the rules are read again.
- "Today", for that count, is the calendar date on the sender's own device, in its own time zone. A device set to the wrong date counts the days wrong.
- A suspension the post office announces for a later date starts on that date by the same device date. Before it, a box to that country gets a note to mail it before then, and is not refused: the app does not know the day the box will actually be mailed. The suspension list changes when the post office updates its page, and the app follows it only when a new rule edition ships.
- Switching cloud checks off (`kill_cloud`) applies to every read that starts afterwards. A read already running when it is switched off can still finish: on Android one hybrid call may fall back to the cloud; on the web, a request already sent can finish; anything not yet sent, including an automatic retry or the fallback model, is not sent.
- A box open in one tab or device does not update while another changes it. Each edit saves only the item it touched, so neither overwrites the other, but the box on screen, and its verdict, shows the other's changes only after a reload.
- Opening a box never writes to it. An item saved with a second look that was changed elsewhere since opens held at "Check this", and that held state is saved only when the sender next edits the item; until then a reload holds it again.
- A saved box this device is not allowed to read (for example one made by another sign-in on the same browser) stays "could not be opened". New edits stay on this device and are not saved; the app does not start a new box in its place.
- An item changed in one place and removed meanwhile in another (on another device, or in another tab of this browser) can come back. The saves go item by item and the later save wins; a tab that opened the box before the other tab's save landed does not know the server holds the item, so its removal may send no delete.
- Two tabs of this browser with the same box open share one list of saves still to send. When one tab saves, it can drop a change the other tab has not sent yet from that list. The other tab still sends the change while it stays open, but if it is reloaded or closed first, the change is lost and the box shows the last value the server got.
- Android does not run the cloud second look. On a phone with an on-device model, that one read and the rules decide, and the card says which read it was.
- The iPhone app runs the cloud second look only for a photo read on the iPhone's own model, and only when the rules ask for one and cloud checks are allowed at that moment (allowed, online, not paused). Label words read on the iPhone get no second look: that one read and the rules decide, and the card says "Read on this iPhone". A look that failed for no connection is tried again by itself up to three times (after a wait, or when the iPhone is back online), and only while the app stays open; then the card says to try again. If the app is closed first, the item keeps its first read and its verdict, and no look runs for it later.
- The label words the rules look for (100 of them, such as alcohol, flammable, aerosol, lithium-ion and power bank) are English only, and the on-device model is asked for English text in and out. On a label in another language none of those words match, so the verdict rests on what the read reports (the category, the battery numbers and the yes-or-no facts) and on the sender's answers.
