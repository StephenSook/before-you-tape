# Known limits

What the app cannot catch on its own, and what it relies on the sender for.

- When a label has "ALCOHOL" at the end of one line and "FREE" at the start of the next, the app asks "Does the label say alcohol-free?". It takes the sender's answer as given: a "yes" on a label whose next line is really "FREE SHIPPING" reads "OK to pack".
- The rules behind each verdict were read on a stated date, and the app marks a layer stale once that read is older than its limit: 120 days for the USPS export rules, 60 days for a country's rules and customs notes, 21 days for USPS service suspensions. While any layer is stale, nothing reads "OK to pack"; it reads "Check this" until the rules are read again.
- "Today", for that count, is the calendar date on the sender's own device, in its own time zone. A device set to the wrong date counts the days wrong.
- A suspension the post office announces for a later date starts on that date by the same device date. Before it, a box to that country gets a note to mail it before then, and is not refused: the app does not know the day the box will actually be mailed. The suspension list changes when the post office updates its page, and the app follows it only when a new rule edition ships.
- Switching cloud checks off (`kill_cloud`) applies to every read that starts afterwards. A read already running when it is switched off can still finish: on Android one hybrid call may fall back to the cloud; on the web, a request already sent can finish; anything not yet sent, including an automatic retry or the fallback model, is not sent.
- A box open in one tab or device does not update while another changes it. Each edit saves only the item it touched, so neither overwrites the other, but the box on screen, and its verdict, shows the other's changes only after a reload.
- Opening a box never writes to it. An item saved with a second look that was changed elsewhere since opens held at "Check this", and that held state is saved only when the sender next edits the item; until then a reload holds it again.
- A saved box this device is not allowed to read (for example one made by another sign-in on the same browser) stays "could not be opened". New edits stay on this device and are not saved; the app does not start a new box in its place.
- An item changed in one place and removed meanwhile in another (on another device, or in another tab of this browser) can come back. The saves go item by item and the later save wins; a tab that opened the box before the other tab's save landed does not know the server holds the item, so its removal may send no delete.
- Two tabs of this browser with the same box open share one list of saves still to send. When one tab saves, it can drop a change the other tab has not sent yet from that list. The other tab still sends the change while it stays open, but if it is reloaded or closed first, the change is lost and the box shows the last value the server got. The same holds when a tab saves again after a delete of the box that failed.
- Delete my saved box on the web needs the internet and this browser's own sign-in; without them it changes nothing and asks you to connect. It deletes the box's items first and the box last. An item or dispute another tab or device saves in the moment between the last check for items and the box's own delete is left behind: once the box is gone no one can read it, and Firestore deletes it automatically when the box would have expired, 37 days after the box was made. The anonymous sign-in is deleted only when it is the one that owned the box. If it can't be deleted right away (it needs a recent sign-in), it is signed out instead, and Firebase may delete it automatically any time after it is 30 days old ([Firebase: automatic clean-up of anonymous accounts](https://firebase.google.com/docs/auth/web/anonymous-auth)).
- A deleted box's id stays retired until 30 days after the box would have expired. A tab still holding that id after then could start a box under it again; nothing of the old box is left to read by then.
- Android does not run the cloud second look. On a phone with an on-device model, that one read and the rules decide, and the card says which read it was.
- The iPhone app runs the cloud second look only for a photo read on the iPhone's own model, and only when the rules ask for one and cloud checks are allowed at that moment (allowed, online, not paused). When the sender never answered the cloud question (or answered its earlier words), the card offers "Check it in the cloud", which asks first; after "Keep everything on this iPhone" nothing is offered or sent. Label words read on the iPhone get no second look: that one read and the rules decide, and the card says "Read on this iPhone". A look that failed for no connection is tried again by itself up to three times (after a wait, or when the iPhone is back online), and only while the app stays open; then the card says to try again. If the app is closed first, the item keeps its first read and its verdict, and no look runs for it later.
- If this iPhone can't save any file when you turn cloud checks off (for example, storage is full), the earlier choice can come back after a restart. The app warns you when this happens.
- On the iPhone, a photo already on its way to the cloud when you remove its item or turn cloud checks off cannot be called back; its reply is not used.
- When Delete everything on this iPhone deletes the anonymous sign-in, Firebase deletes it on its servers first. If the iPhone then cannot remove it from its keychain, a copy can stay on the iPhone; it no longer works.
- The label words the rules look for (100 of them, such as alcohol, flammable, aerosol, lithium-ion and power bank) are English only, and the on-device model is asked for English text in and out. On a label in another language none of those words match, so the verdict rests on what the read reports (the category, the battery numbers and the yes-or-no facts) and on the sender's answers.
- Offline, the web app opens only after one visit online, and only on its own pages; others, such as the privacy page, need the network. Offline, a photo is read only by the browser's built-in model; with none, the page says it is offline and asks you to type the item. Saves wait until you are back online.
- A new version reaches an open page only when you press Reload on the line that says one is ready; until then the page runs the version it opened with, and Reload in one tab reloads only that tab. A tab looks for a new version when it is shown again and every hour. A tab still open two versions back can fail to load a file the worker no longer keeps; reloading it fixes that. If the service worker itself goes wrong, the kill switch in [`SECURITY.md`](SECURITY.md) removes it, and reloads each open tab once without asking. The kill worker being stopped part way through its cleanup is not tested (a browser cannot be stopped there reliably in a test); the kill build's page repeats the cleanup on every load, so the next visit ends clean either way.
- The kill switch is for emergencies only. A page of a kill build that opens late, after a normal deploy has brought the worker back, removes that worker again; it comes back on that tab's next visit.
- A tab that opened with no worker yet (the first visit) can miss the line that a newer version is ready if that version takes over while the page is still starting; it shows on the next visit or reload.
- A tab left open on a kill build does not look for a new version; it gets the restored worker when it is reloaded.
- A deploy goes live before its checks run, and a failed check rolls it back. A visitor who opened the site in those few minutes keeps the rolled-back version until they press Reload on the line that offers the restored one.
- The holiday mailing date is the one USPS lists for Priority Mail International on its holiday page, read on 2026-11-21: a recommended mail-by date for expected delivery before December 25, not a promise. The days left count by this device's own date, and no date shows for a country whose mail stops before it.
- The Rules page quotes Canada's customs authority on duty and tax for mailed items and gifts, word for word, and shows no values, totals or conversions. The Philippines has no such line: its Bureau of Customs site answered HTTP 403 to both a script and a browser on 2026-11-21, so its own wording could not be checked there.
